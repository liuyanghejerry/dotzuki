# 编排高密度地图布景

> - **Audience**: game authors, tool developers
> - **Type**: how-to

> - **Last verified**: v0.8.2

在已有地图上移动精细像素素材，分别维护逻辑网格和碰撞数据。

开始前，请阅读[地图指南](./maps.zh-CN.md)和[关联建筑编辑](./map-components.zh-CN.md)，并在[项目清单](../reference/project-manifest.md)中配置 map 和 tiles 活动。

## 准备兼容地图

[原生布景](../reference/glossary.md#native-map-scenery)使用放在 `map.tmx.json` 旁的可选 `art.json`。游戏运行端需要支持这份布景协议。本编辑器功能不会修改通用 runner 的渲染，也不会自动转换地块地图。

对于 4×3 格、每格 16×16 逻辑像素的地图，准备 128×96 的地面 PNG 和 32×64 的树木 PNG，并保存为已配置素材目录中的可编辑建筑组件。下面假设 `maps` 和 `tiles` 是同级目录：

```json
{
  "version": 1,
  "pixels_per_unit": 2,
  "ground": "../../tiles/groups/ground.png",
  "components": [
    {
      "image": "../../tiles/groups/tree.png",
      "x": 16,
      "y": 0,
      "foot_y": 16,
      "layer": "depth"
    }
  ]
}
```

图片路径相对于地图目录，解析后须位于配置的数据根目录内。密度是 1 至 4 的整数。地面尺寸等于地图格数 × 逻辑格尺寸 × 密度；组件图片尺寸须能被密度整除。可选的 `water_mask` PNG 须与地面同尺寸。编辑器可以显示蒙版供检查，但不播放水纹动画。

## 编排和检查物件

1. 打开地图，点击 **原生布景**。新标签页显示完整地面和组件，保留清晰像素边缘。100% 倍率下，每个来源像素占一个 CSS 像素。
2. 点击物件的不透明部分，或从筛选后的物件列表选择。图片透明角落允许选中下面的物件。
3. 拖动物件。**吸附网格**将移动量对齐逻辑网格。方向键移动一个逻辑像素，Shift + 方向键移动一格。也可以直接设置 **X**、**Y** 和 **排序脚底 Y**。修改 Y 会同步移动排序锚点。
4. 桥面和地面细节选择 **地面**；建筑、树木选择 **按脚底排序**；固定覆盖物选择 **前景**。深度物件按 `foot_y` 排序，同值时保持原组件顺序。青色线表示所选物件的排序锚点。
5. 启用 **碰撞**、**网格**或**人物与出入口**，对照已保存的地图数据。这些叠层显示底层碰撞和静态物件位置；条件事件和人物走位仍需试玩。碰撞与角色位置在地块标签页中修改，保存后重载布景页。
6. 选择素材库图片，点击 **放置素材库物件**，将其加入当前可见区域中心附近。也可以复制或移除已有物件。这些操作仅改变布景，不会新增或删除碰撞格。

## 编辑像素并保存

选择组件后点击 **编辑像素**，会在现有像素编辑器中打开对应建筑组件。地面也有独立编辑按钮。在像素编辑器中保存 PNG 和图层，再返回布景页；来源图片会更新，未保存的位置和撤销历史会保留。

**保存布景**只写入 `art.json`，保留未知的顶层字段和组件字段。保存后仍可撤销/重做；撤销已保存的修改会使标签页重新变为未保存状态。切换标签页会保留各自的布局，关闭未保存的布景页前会询问是否丢弃。

如果其他工具在打开后修改了 `art.json`，保存会报告冲突，并保留磁盘文件和当前未保存布局。先检查外部修改，再选择 **从磁盘重载**；确认后会丢弃本地布局。图片缺失、地面尺寸错误、密度无效或组件尺寸无法整除密度时，保存不会写入文件。
