# DSL codegen 约定

> 本文是 `reference/dsl/codegen.md` 的中文翻译，同步至引擎版本 v0.1.0（源文档 commit 3133fb419ae3bc6e5c08bbbcd43ac7fa0289e44f）。
> 内容以英文源为准；发现不一致请更新英文源再同步翻译。

线编译为 JavaScript，UI 布局、主题、样式与 atlas 编译为 JSON——均与
`crates/dotzuki-engine-dsl/src/` 中的编译器源码核对过。

> - **Audience**: DSL authors, compiler maintainers
> - **Type**: reference
> - **Status**: active

## 编译管线

- 四种文件扩展名：`.scene`、`.gui`、`.theme`、`.style`（compiler.rs:74）。
- 解析前，`.theme` 与 `.style` 文件内容会被包进 `game_scene _auto { ... }`，因此它们
  的块按场景指令解析（compiler.rs:199-205）。
- 管线：lex → parse → 语义校验 → codegen（compiler.rs:199-231）。
- 语义校验拒绝：条件、赋值与 speaker 名字中的未定义变量；空的 `@choice`；缺失或循环
  的 `@style` 父样式；重复的 `@theme`/`@style` 名字（parser.rs:1728-1905）。

构建期编译器写出的产物（compiler.rs:291-343）：

| Source | 产物 |
|---|---|
| `.scene` | `<Scene>.js`；存在 `ui` 块时产出 `<Scene>_ui.json`；每个 `@theme` 产出 `<Scene>_theme_<i>.json`；存在 `@style` 块时产出 `<Scene>_styles.json`；每个 `@atlas` 产出 `<Scene>_atlas_<i>.json` |
| `.gui` | `<Screen>.json` |
| `.theme` | 每个 `@theme` 块产出 `<ThemeName>.json` |
| `.style` | `<Scene>_styles.json`——包装场景的名字是 `_auto`，因此独立的 `.style` 文件写出 `_auto_styles.json` |

- 构建期产物以 `// @generated by dotzuki-engine-dsl — do not edit.` 与
  `// Source: <path>` 开头（compiler.rs:240-241、301-304）。
- `.js` 产物以内联 base64 的 `//# sourceMappingURL` 结尾（compiler.rs:288-289）。
- 产物只在内容变化时重写（`write_if_changed`，compiler.rs:617-635）。

## 两个执行目标

这个 crate 既产出 JS，也自带一个原生 AST 解释器，可以完全不依赖 JS 引擎执行 `.scene`
AST：

- 解释器是场景语义的权威实现；编译 JS 路径（`dotzuki-engine-script` 的 Boa 引擎）是
  后备方案（interpreter.rs:1-24）。
- 解释器拒绝的语句会在下面各节中标注。

## 场景模块形态

`game_scene <Name> { ... }` 按以下顺序编译为一个 JS 模块（compiler.rs:234-289）：

1. 先是 `@variables` 声明——每条声明一条 `let <name> = <value>;`
   （js_variables.rs:21-46）。
2. 每个 `@storyline("name")` 块按声明顺序输出一个
   `export async function storyline_<name>() { ... }`（compiler.rs:257-280）。旧式
   未命名 `@storylines { ... }` 块变成 `storyline_main()`，不带 trigger 绑定
   （parser.rs:684-692、js_storyline.rs:494-502）。
3. 存在 `@load` 块时输出 `export async function <SceneName>OnLoad() { ... }`
   （js_storyline.rs:504-511）。

## 剧情线语句

在 `@storyline`/`@storylines`/`@load` 体以及 `@if`、`@choice`、`@each` 分支内合法的
语句形式（parser.rs:1011-1034）。

### `@speaker` / `@say`

```dsl
@speaker("Prof") {
    "Hello! Welcome to the world of monsters!"
}
```

编译为（js_storyline.rs:197-259）：

```js
await game.showText("Prof: Hello! Welcome to the world of monsters!");
```

- 非空字符串字面量名字会以 `"Name: "` 形式前置于输出的字符串中。
- `@speaker("")` 是旁白形式：内容原样输出，不带前缀（js_storyline.rs:217-223）。
  回归测试 `test_speaker_empty_name_no_prefix`（js_storyline.rs:633-652）。
- 变量名字编译为模板字符串：`` `${name}: text` ``（js_storyline.rs:225-228）。
- 一个块内的多行文本用 `\n` 拼接（js_storyline.rs:212）。
- `@speaker` 与 `@say` 输出完全相同的 JS；区别在语义——`@speaker` 是玩家发起的交谈，
  `@say` 是过场对白（ast.rs:221-230、js_storyline.rs:184-196）。
- 本地化的 `@t(...)` 行经 `game.t("en", "zh")` 编译（js_storyline.rs:229-254）。

### `@choice` / `@option`

```dsl
@choice {
    @option("Yes") {
        @speaker("Prof") { "Great!" }
    }
    @option("No") {
        @speaker("Prof") { "Too bad." }
    }
}
```

编译为（js_storyline.rs:266-319）：

```js
const choice = await game.showChoice(["Yes", "No"]);
if (choice === 0) {
    await game.showText("Prof: Great!");
} else {
    await game.showText("Prof: Too bad.");
}
```

- 最后一个选项是 `else` 分支；每个更早的选项得到 `if (choice === N)` 或
  `else if (choice === N)`（js_storyline.rs:297-305）。

### `@if` / `@else` —— 条件编译（已定论）

DSL 条件是表达式 AST，由 `compile_expression` 编译（js_storyline.rs:76-140），再由
`compile_if` 包裹（js_storyline.rs:322-363）。以下事实与旧版 `DSL_MAPPING.md` §3 及
条目 4 相矛盾：

- `@if (gold > 100) { ... } @else { ... }` 编译为：

```js
if ((gold > 100)) {
    ...
} else {
    ...
}
```

- 条件被加了两层括号：`compile_expression` 给每个二元运算加 `(...)`，`compile_if`
  输出 `if ({cond})`（js_storyline.rs:120、338）。
- DSL 中的 `==` 编译为 JS 的 `===`（js_storyline.rs:37）。解释器同样使用严格相等
  （interpreter.rs:111-119）。
- 条件中裸调用的被调方会加上 `game.` 命名空间：`@if (getFlag("EVENT_X"))` 编译为
  `if (game.getFlag("EVENT_X"))`（js_storyline.rs:99-108；回归测试
  `test_condition_calls_are_game_namespaced`，tests/codegen_tests.rs:954-978）。
- 未定义的变量名不会经由 `game.getFlag()` 解析。它们在编译期以 `UndefinedVariable`
  语义校验失败（parser.rs:1791-1798）。旧文档声称"匹配已知 flag 的未定义名字会编译为
  `game.getFlag()`"，代码中不存在这种行为。
- else-if 链写作 `@else @if (...) { ... }`。解析器把它脱糖为 else 分支内嵌套的 `If`
  （parser.rs:1134-1173），所以 JS 是嵌套结构，而非扁平的 `else if` 链：

```dsl
@if (gold > 100) {
    @speaker("") { "rich" }
} @else @if (gold > 10) {
    @speaker("") { "mid" }
} @else {
    @speaker("") { "poor" }
}
```

```js
if ((gold > 100)) {
    await game.showText("rich");
} else {
    if ((gold > 10)) {
        await game.showText("mid");
    } else {
        await game.showText("poor");
    }
}
```

- 写成 `@else if`（`if` 前没有 `@`）是解析错误：
  `expected one of [LBrace], found Identifier("if")`。
- 在原生解释器中，`@if` 条件只能经由同步查询求值；条件中出现异步命令是错误
  （interpreter.rs:459-473）。

### `@each`

```dsl
@each item in inventory {
    @speaker("") { "..." }
}
```

编译为 `for (const item of inventory) { ... }`（js_storyline.rs:366-396）。`in` 关键字
可选（parser.rs:1189-1197）。

### 赋值语句

- `gold = 500` 编译为裸的 `gold = 500;`。`let gold = 500;` 声明提升到剧情线函数顶部
  （js_storyline.rs:398-428、531-576）。
- 值为调用的赋值留在原地并 await：`result = startBattle("OPP")` 编译为
  `result = await game.startBattle("OPP");`，带提升的 `let result;`
  （js_storyline.rs:409-418、557-571）。
- 给 `@variables` 名字赋值会修改模块作用域的变量；不会输出局部 `let`
  （js_storyline.rs:543-554）。

### 裸命令与 `@command`

```dsl
heal()
giveItem("Potion", 1)
fadeScreen("out")
```

编译为（js_storyline.rs:461-481）：

```js
await game["heal"]();
await game["giveItem"]("Potion", 1);
await game["fadeScreen"]("out");
```

- `@command("heal")` 与 `@command("giveItem", "Potion", 1)` 编译结果相同；第一个实参
  必须是字符串字面量（parser.rs:1252-1304）。
- 不带圆括号的裸标识符同样是命令：`heal` → `await game["heal"]();`
  （parser.rs:1218-1245）。
- 裸标识符后跟 `=` 是赋值；否则是命令（parser.rs:1020-1023）。

### `@run { ... }` —— 原生 JavaScript（已定论）

两份旧文档说法不一：`DSL_MAPPING.md` 条目 14 称 `@run` 是当前一等公民的逃生通道；
归档设计报告称所有 `@run` 块都作为反模式从 pokered 语料中移除。编译器代码的说法是：

- `@run { ... }` 把块按原始文本词法化，并跟踪花括号嵌套（lexer.rs:491-543），得到
  `StoryStmt::Run`（parser.rs:988-1009）。
- codegen 原样输出每个非空行，前缀补上编译器的缩进；作者的内层缩进保留；空行保留；
  不生成 sourcemap 条目（js_storyline.rs:55-74）。
- `@run` 在 `parse_story_stmt` 运行的所有位置都合法：剧情线体、`@load`、`@if`/`@else`
  分支与 `@choice` 选项体（parser.rs:1011-1034）。在 `game_scene` 顶层不合法
  （parser.rs:679-720）。
- 语义校验器完全跳过 `@run` 内容：其中的 JS 标识符不会产生未定义变量错误
  （parser.rs:1774、1826、1845）。
- 原生 AST 解释器报错拒绝 `@run`（"unsupported statement: @run raw-JS blocks cannot
  run in the native interpreter"，interpreter.rs:524-528）。

净效果：`@run` 在 JS/Boa 运行时路径上可以编译，但被权威解释器拒绝。两份旧描述都不
完整；两种行为在当前代码中共存。

## `@variables`

```dsl
@variables {
    gold = 500
    player = { name: "RED", level: 5 }
    inventory = ["sword", "shield"]
}
```

编译为（js_variables.rs:21-46）：

```js
let gold = 500;
let player = { name: "RED", level: 5 };
let inventory = ["sword", "shield"];
```

- 对象字面量使用 `key: value`（冒号）。`{ name = "RED" }` 是解析错误：
  `expected one of [Colon], found Equals`（parser.rs:424-451）。
- 没有 `const` 形式；每条声明都是 `let`。
- 调用形式的初始化器不会加 `game.` 命名空间：`flag = getFlag("EVENT_X")` 编译为
  `let flag = getFlag("EVENT_X");`（js_variables.rs:93-96）——与剧情表达式不同，后者
  会加 `game.getFlag(...)`。

## 表达式

`compile_expression`（js_storyline.rs:76-140）把表达式 AST 映射为 JS：

| DSL 表达式 | JS 输出 |
|---|---|
| `"text"` | JSON 转义后的字符串字面量 |
| `42` / `3.14` | `42` / `3.14`（整数不带 `.0` 输出） |
| `true` / `false` | `true` / `false` |
| `gold` | `gold` |
| `[1, 2]` | `[1, 2]` |
| `{ a: 1, b: 2 }` | `{ a: 1, b: 2 }` |
| `getFlag("X")` | `game.getFlag("X")` |
| `!x` / `-x` | `(!x)` / `(-x)` |
| `a + b`（任意二元运算） | `(a + b)` |
| `c ? t : e` | `(c ? t : e)` |

- 运算符映射：`==`→`===`、`!=`→`!==`、`&&`、`||`、`|`、`&`、`+ - * / > < >= <=`
  （js_storyline.rs:31-48）。
- 标识符可以包含 `.` 与 `-`（lexer.rs:438-447）。带点的名字是一个标识符，不是成员
  访问。因此在 DSL 中写 `game.getFlag("X")` 会编译为 `game.game.getFlag("X")`——请
  改写成裸的 `getFlag("X")`。
- 字符串插值（字符串内的 `{expression}`）没有实现：词法器原样读取字符串
  （lexer.rs:376-400），也没有任何 codegen 阶段把 `{...}` 提取成 JS 模板字符串。旧版
  `DSL_MAPPING.md` 条目 6 描述的特性在这个编译器中不存在。存在的是 GUI 绑定约定：
  用作 UI 属性的变量会编译为字符串 `"{name}"` 交给渲染器（json_ui.rs:366-385）。GUI
  模板绑定在模板字符串内使用宽松的 `==`/`!=`（json_ui.rs:493-510），而 JS 代码与
  解释器使用严格相等。

## UI JSON（`.gui` 与 `ui { }` 块）

- `.gui` 的 `screen <Name> { ... }` 编译为
  `{"schema_version": 2, "screen": "<Name>", "elements": [...]}`（json_ui.rs:40-49）。
- `screen <Name> : <theme>` 能解析出主题名（parser.rs:735-738），但输出的 JSON 不
  包含它（json_ui.rs:40-49）。
- `.scene` 的 `ui { ... }` 块编译为 `{"type": "group", "children": [...]}`
  （json_ui.rs:28-35）。
- 组件映射（json_ui.rs:52-240）：

| DSL 组件 | JSON 输出 |
|---|---|
| `panel { ... }` | `{ "type": "border", "children": [...] }` |
| `container { ... }` | `{ "type": "group", "children": [...] }` |
| `text("Shop") {}` | `{ "type": "text", "value": "Shop" }` |
| `button("Buy") { on_click = "buy" }` | `{ "type": "text", "value": "Buy", "interactive": true, "onClick": "buy" }` |
| `list { source = items }` | `{ "type": "list", "items": "{items}" }` |
| `flex_list(items)` | `{ "type": "flex_list", "items": "{items}" }` |
| `image("ui.png") { slice = "[8,8,8,8]" }` | `{ "type": "image", "src": "ui.png", "nineSlice": "[8,8,8,8]" }` |
| `tile(31) { rect = {...} }` | `{ "type": "tile", "tile_id": 31, "rect": {...} }` |
| `divider { tiles = [122] }` | `{ "type": "divider", "tiles": [122] }` |
| `input` / `dropdown` | `{ "type": "custom:input" }` / `{ "type": "custom:dropdown" }` |
| `cursor` / `bracket` / `pixel_rect` | `{ "type": "cursor" / "bracket" / "pixel_rect" }` |
| 声明的 `component` 使用 | `{ "type": "custom:<name>" }` |

- 每个组件都必须带 `{ ... }` 块，即使为空（`text("Hi") {}`）。不带块的 `text("Hi")`
  是解析错误。
- 带名字的子组件 `title = text("Shop") {}` 会携带 `"id": "title"`
  （parser.rs:1324-1353、json_ui.rs:246-249）。
- prop 名映射：`on_click` → `onClick`、`flex_grow` → `flexGrow`（json_ui.rs:246-267）。
- 单个数值 `padding = 24` 会展开为 `[24, 24, 24, 24]`；单个非数值保持为标量
  （parser.rs:1464-1470、json_ui.rs:351-359）。
- `text()`/`button()` 的非字符串位置实参会产出空字符串（parser.rs:1928-1934）。
- 旧版 `DSL_MAPPING.md` 条目 7/8 展示的是 `{"type": "panel"}` 与
  `{"type": "button", "label": ...}`——真正输出的类型是 `border` 与 `text`（带
  `interactive`），如上所示。

## `@theme`

完整参考见 [theme-style.md](theme-style.md)。代码事实（json_theme.rs:9-15、
compiler.rs:378-393）：

```dsl
@theme dark {
    primary = "#c9a03d"
    background = "#1a1a2e"
}
```

编译为 `{"name": "dark", "tokens": {"primary": "#c9a03d", "background": "#1a1a2e"}}`。

- token 只接受字符串（parser.rs:1579-1582）。
- 每个 `@theme` 写出自己的 `<ThemeName>.json` 文件；含多个块的 `.theme` 文件产出多个
  文件，而非单个 map（与旧版 `DSL_MAPPING.md` 条目 9 相矛盾）。

## `@style`

完整参考见 [theme-style.md](theme-style.md)。代码事实（json_theme.rs:45-141）：

- 继承在编译期解析。输出是样式对象的 JSON 数组，每个对象带 `name`、合并后的
  `properties`（子覆盖父）、声明过继承时的 `extends`，以及链上成员多于一个时的
  `inheritance_chain`。
- 属性值：字面量成为 JSON 原始值；变量成为 `{"$var": "<name>"}`
  （json_theme.rs:132-141）。
- 循环继承是编译期错误（`CircularStyleInheritance`，parser.rs:1862-1868）；父样式
  缺失是 `MissingStyleParent`（parser.rs:1853-1861）。
- 旧版的 `__extends` 字段不存在；字段名是 `extends`（与旧版 `DSL_MAPPING.md` 条目 10
  相矛盾）。

## `@atlas`

```dsl
@atlas "ui" {
    source = "assets/ui/atlas.png"
    regions = {
        btn = [0, 0, 64, 64, slice=8]
    }
}
```

编译为（json_atlas.rs:35-65）：

```json
{
  "name": "ui",
  "source": "assets/ui/atlas.png",
  "regions": [
    {
      "name": "btn",
      "x": 0, "y": 0, "w": 64, "h": 64,
      "nineSlice": { "top": 8, "right": 8, "bottom": 8, "left": 8 }
    }
  ]
}
```

- region 的键是 `w`/`h`，不是 `width`/`height`（与旧版 `DSL_MAPPING.md` 条目 11 相
  矛盾）。
- `slice=8` 展开为四条相等的边；`slice=[top, right, bottom, left]` 逐边映射
  （parser.rs:1702-1718）。没有 `slice` 的 region 省略 `nineSlice`（json_atlas.rs:56-63）。

## Trigger 绑定 → `script_config.json`

`@storyline` 中的 `@trigger` 字段会重新生成地图的 `script_config.json`
（config_gen.rs:18-99）。运行时契约见 [project-manifest.md](../project-manifest.md)。

- `npc = N`（数字或数字字符串）→ 一个 `npcs[]` 条目
  `{ "id": N, "talk": "<storyline>" }`，给定 `toggle`/`script`/`hidden` 时附加
  `toggleId`/`scriptId`/`defaultHidden`；`no_talk = true` 省略 `talk`
  （config_gen.rs:28-43）。非数字字符串填入旧式的建议性 `npc` 名字字段，仅用于路由
  与冲突分组（parser.rs:893-900）。
- `sign = N` → 一个 `signs[]` 条目 `{ "id": N, "talk": "<storyline>" }`
  （config_gen.rs:45-47）。
- `coord = [x, y]` / `coords = [[x, y], ...]` → `coordEvents[]` 条目
  `{ "name": ..., "position": [x, y], "trigger": "<storyline>" }`
  （config_gen.rs:49-72）。
- coord 名字推导：只有一个 coord 时用 `name` 字段；多个 coord 时去掉结尾数字并重新
  编号（`northExit1` → `northExit1`、`northExit2`、……）；未命名的 coord 得到
  `<storyline>_<x>_<y>`（config_gen.rs:50-70）。
- 任何 `@load` 块都会把 `onLoad` 设为 `<SceneName>OnLoad`（config_gen.rs:81-83）。
- 每个绑定一行 `@trigger`；一条剧情线可以携带多行 `@trigger`（parser.rs:807-840）。
- `after` 把剧情线关联起来用于冲突检测：同一 `(map, npc)` 上的两条剧情线如果没有
  `after` 链，会在编译诊断中产生 `CONFLICT` 警告（conflict.rs:16-96）。仅 `onEnter`
  的路由不参与（conflict.rs:38-44）。
- 编译器还可以通过 `compiler::generate_routing_table` 输出建议性的
  `storyline_routes.json`（`{"routes": [...]}`）（compiler.rs:639-645）；运行时路由由
  `script_config.json` 驱动。

## `@t("en", "中文")` i18n

- 语言代码按位置排列：第一个实参是 `en`，第二个是 `zh`；多余的实参归入 `und`
  （parser.rs:492-526）。
- 场景 JS：`@t(...)` 编译为 `game.t("en", "zh")`（i18n.rs:10-30、js_storyline.rs:79）。
- GUI JSON：`@t(...)` 编译为 `{"en": "...", "zh": "..."}`，由渲染器在绘制时解析
  （json_ui.rs:12-23）。

## 原生 AST 解释器（权威语义）

`interpreter.rs` 直接执行 `.scene` AST，与 Boa 运行时协议 1:1 对齐（interpreter.rs:1-24）：

- 支持：`@speaker`/`@say`、`@choice`/`@option`、`@if`/`@else`、`@each`、裸命令、赋值。
- 拒绝：`@run`（interpreter.rs:524-528）、对象字面量（interpreter.rs:670-674），以及
  条件或表达式中的异步命令（interpreter.rs:465-472、543-556）。
- `showChoice` 结果越界时落到最后一个选项（interpreter.rs:361-371），与 JS 的 `else`
  形态一致。

## 待定问题

- `@run` 的去向：编译器与 JS 运行时路径接受 `@run`（js_storyline.rs:60-74），权威
  解释器拒绝它（interpreter.rs:524-528）。`DSL_MAPPING.md` 条目 14 称它是当前一等
  公民的逃生通道；归档设计称它是被移除的反模式。哪种行为是长期契约的目标，是代码
  没有言明的设计决策。
- `@variables` 的调用形式初始化器输出时不带 `game.` 命名空间
  （`let flag = getFlag("EVENT_X");`，js_variables.rs:93-96），与剧情表达式
  （`game.getFlag(...)`，js_storyline.rs:99-108）不同。语义校验器允许调用形式的
  初始化器（parser.rs:1741-1751）。`@variables` 初始化器是否允许包含调用尚无定论。
- 语料状态声明：归档设计的核验数字（248 张地图、零个 `@run` 块、10 张地图的条件中
  含未内联常量）与 `DSL_MAPPING.md` 的配置往返声明描述的是 pokered 游戏语料，位于本
  仓库之外。无法在本仓库核验。
- `storyline_routes.json` 的消费方：编译器可以写出该文件（compiler.rs:639-645），
  crate 内的冲突检测器在内存中的路由上工作，不读取它（conflict.rs:16-96）。
  `DSL_MAPPING.md` 条目 13 称该 JSON 驱动一个构建期冲突检测器；本 crate 中不存在
  `generate_routing_table` 的调用方，因此消费方尚无定论。
