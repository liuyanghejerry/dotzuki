## 更新依赖和输入掩码

将所有 dotzuki 依赖一并更新至 registry 版本 `0.11.0` 或 git 标签 `v0.11.0`。
刷新游戏及独立目标清单各自的锁文件。

渲染器中的 `GbButton::bit_mask`、`InputState::raw_current` 和
`InputState::raw_previous` 返回 `u16`。`InputState::set_from_bitmask` 接受 `u16`。
将保存的掩码扩为 16 位，导入八位值时使用 `u16::from(mask)`。位 0–7 保留原有定义。
穷举匹配需处理 `GbButton::R`（位 8）和 `GbButton::L`（位 9）。用 `GbButton::ALL.len()`
确定按键数组长度。键盘上的 Q 对应 L，E 对应 R。参见[游戏外壳参考](../../reference/game-shell.zh-CN.md#运行时行为)。

## 保存 NPC 移动状态和游戏进度

给空闲 NPC 的 `NpcRuntimeState` 字面量补上 `step_direction: None`。若 NPC 正在迈步，
则填入 `Some(direction)`，其中方向取开始迈出这一步时的移动方向。用 `walking_direction()`
预测移动和占用的格子，用 `facing` 绘制角色。旧 JSON 快照读取新字段时默认为 `None`，
使用存档里的原朝向。二进制适配器需兼容旧布局，并在新快照中保存该步的移动方向。

构造新游戏的 `dotzuki_runner::save::GameSave` 字面量时，填入 `heal_point: None`。
场景中的 `heal()` 会将玩家的地图、格子、朝向和海拔层记录为[回复点](../../reference/glossary.md#battle-gameplay)。
v3 JSON 存档将该字段视为可选。加载旧存档后，玩家会在入口出生点重生，直至场景记录回复点。
参见[存档兼容性](../../explanation/save-compatibility.zh-CN.md)。

## 选择战斗钩子的持有者

在 `dotzuki_rules::HookRecord` 或 `CompiledHook` 的 Rust 字面量中填入
`holder: HookHolder::Attacker` 可保留原有行为。若防守方的特性或携带道具应响应来袭技能，
则使用 `HookHolder::Defender`。已有的 [rules.ron](../../reference/glossary.md#engine)
文件默认选择攻击方。参见[战斗规则](../../reference/battle-rules.zh-CN.md)。

## 更新音频和移动端适配器

`dotzuki_audio::effects::init_pitch_slide` 返回音符起音时应写入寄存器的 `u16` 值。
请相应更新函数指针的返回类型。返回 `()` 的包装函数可将该调用写成一条语句。
给新通道的 `ChannelState` 字面量补上 `resting: false`。通道处于定时休止时，
自定义[音序器](../../reference/glossary.md#audio)快照需保留 `resting: true`。

如果[移动外壳](../../reference/glossary.md#engine)调用 `dotzuki_mobile_pointer_click` 或
`dotzuki_mobile_cancel_pointer_input`，请将更新后的 C 头文件和 Rust 运行时一并交付。
两个版本的 ABI 版本号均为 1，旧运行时未导出这两个符号。仅处理按键的外壳可沿用其回调。
参见[点击移动](../../how-to/maps.zh-CN.md#点击移动)。

## 验证升级

用更新后的锁文件分别构建各宿主。测试短按肩键、恢复迈步途中的 NPC 和加载升级前的存档。
在触发强制换人的战斗中，确认对手尚未执行的行动会作用于新上场的成员。
如果游戏使用移动端指针回调，请将外壳与准备随包发布的运行时链接。
