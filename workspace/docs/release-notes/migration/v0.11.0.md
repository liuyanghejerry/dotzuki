# Migrating to v0.11.0

> - **Audience**: rust developers, game authors
> - **Type**: how-to
> - **Status**: active
> - **Last verified**: v0.11.0

Update Rust integrations for ten-button input, NPC movement, battle hooks, saves, and audio.
Before you start, read the [changelog](../changelog.md). When upgrading from an earlier
version, also read the [v0.10.1 migration guide](v0.10.1.md).

## Update dependencies and input masks

Update all dotzuki dependencies together to registry version `0.11.0` or git tag `v0.11.0`.
Refresh the lockfiles for the game and any standalone target manifests.

In the renderer, `GbButton::bit_mask`, `InputState::raw_current`, and
`InputState::raw_previous` return `u16`. `InputState::set_from_bitmask` takes a `u16`.
Widen stored masks and use `u16::from(mask)` when importing an eight-bit value. Bits 0–7
retain their assignments. Handle `GbButton::R` (bit 8) and `GbButton::L` (bit 9) in
exhaustive matches. Size button arrays from `GbButton::ALL.len()`. On the keyboard, Q
maps to L and E maps to R. See the [game shell reference](../../reference/game-shell.md#runtime-behavior).

## Preserve NPC movement and saves

Add `step_direction: None` to idle `NpcRuntimeState` literals. For an NPC partway through
a step, supply `Some(direction)` with the direction at the start of that step. Use
`walking_direction()` to predict movement and occupied tiles. Use `facing` to draw the sprite.
Legacy JSON snapshots default the new field to `None` and fall back to their saved facing.
Update binary adapters to read the old layout and retain the step direction in new snapshots.

In `dotzuki_runner::save::GameSave` literals, add `heal_point: None` for a new game.
A scene's `heal()` records the player's map, tile, facing, and elevation as a
[heal point](../../reference/glossary.md#battle-gameplay). The field is optional in version 3
save JSON. Games can load existing saves and respawn at the entry spawn until a scene records
a heal point. See [save compatibility](../../explanation/save-compatibility.md).

## Select a battle hook holder

For Rust literals of `dotzuki_rules::HookRecord` or `CompiledHook`, use
`holder: HookHolder::Attacker` to retain the previous behavior. Use `HookHolder::Defender`
when the defender's ability or held item should react to the incoming skill.
Existing [rules.ron](../../reference/glossary.md#engine) files default to the attacker.
See [battle rules](../../reference/battle-rules.md).

## Update audio and mobile adapters

`dotzuki_audio::effects::init_pitch_slide` returns a `u16` for the note's onset register.
Update typed function pointers to accept the return type. Wrappers that return `()` can call
the function as a statement. Add `resting: false` to `ChannelState` literals for new
channels. In custom [sequencer](../../reference/glossary.md#audio) snapshots, retain
`resting: true` while a timed rest is in progress.

If a [mobile shell](../../reference/glossary.md#engine) calls `dotzuki_mobile_pointer_click`
or `dotzuki_mobile_cancel_pointer_input`, ship the updated C header and Rust runtime together.
Both releases report ABI version 1. The older runtime lacks these two exports. Button-only
shells can keep their existing callbacks. See [click to move](../../how-to/maps.md#click-to-move).

## Verify the upgrade

Build each host with its updated lockfile. Test a shoulder-button tap, restore an NPC midway
through a step, and load a save created before the upgrade. In a battle that forces a switch,
check that the opponent's pending action reaches the replacement. If the game uses a mobile
pointer callback, link the shell against the runtime that will ship with it.
