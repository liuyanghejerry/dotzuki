# Migrating to v0.12.0

> - **Audience**: rust developers, game authors
> - **Type**: how-to
> - **Status**: active
> - **Last verified**: v0.12.0

Update custom battle hosts and package compatible players with your exports.
Before you start, read the [changelog](../changelog.md). For upgrades from
versions earlier than v0.11.0, also read the [previous migration guide](v0.11.0.md).

## Update battle hosts

Update all dotzuki dependencies together to registry version `0.12.0` or git tag
`v0.12.0`. Refresh the game's lockfile and the lockfiles of any standalone targets.

If your host constructs [battle hook state](../../reference/battle-rules.md#rules-ownership-in-the-zero-rust-runner)
directly, compile the project's definitions with `BattleRules::compile(&ruleset, resource)`.
Wrap the result in an `Arc` and pass a clone to
`HookState::new(rules, &player, &enemy)` for each encounter. Read the compiled hooks
and stat names from `state.rules.compiled().hooks` and `state.rules.compiled().stats`.
Access move records, status names, and the resource setting through
`state.rules.move_records`, `state.rules.status_names`, and `state.rules.has_resource`.
Hosts that call `BattleSetup::from_project` get shared definitions automatically.

## Rebuild players and exports

Run `dotzuki export` again for each target that should ship
[compiled scene assets](../../reference/glossary.md#compiled-scene-assets).
Use a matching Web runner package or native player to load native functions on demand.
Older players read the bundled sources. Projects opened from disk keep source hot reload.

If your [mobile shell](../../explanation/mobile-architecture.md) calls
`dotzuki_mobile_copy_frame_update`, rebuild the Rust runtime archive and link it with
the matching C header. The symbol is optional in ABI v1. Hosts that take full-frame
snapshots can continue calling `dotzuki_mobile_copy_frame`.

## Verify the upgrade

Open an existing save, revisit a map, and finish a battle. For a game with a custom
hook host, start a second encounter and check that HP and volatile effects start from
that encounter's own state. Run an exported scene on the player you intend to ship.
If the game uses raw JavaScript in `@run`, exercise that storyline as well.
