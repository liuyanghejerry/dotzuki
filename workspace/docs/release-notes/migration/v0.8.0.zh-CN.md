# 迁移到 v0.8.0

> 本文是 `v0.8.0.md` 的中文翻译，同步至引擎版本 v0.8.0
>（源文档 commit db41ffc61f12a1b3cade92ef0c9d33a4db1062ee）。

> - **Audience**: rust developers, game authors
> - **Type**: how-to
> - **Status**: active
> - **Last verified**: v0.8.0

把所有 `dotzuki-*` 依赖从 v0.7.1 更新到 v0.8.0，并完成下面的 feature 与
公开类型迁移。

开始前，请阅读[变更日志](../changelog.zh-CN.md)了解本版本的范围。

## 更新依赖

所有引擎 crate 应使用同一个版本。使用 registry 依赖时：

```toml
dotzuki-engine = "0.8.0"
dotzuki-renderer = "0.8.0"
```

使用 git 依赖时，把每个引擎依赖更新为 `tag = "v0.8.0"`，然后运行：

```bash
cargo update
```

## 启用移到 feature 后的 API

`FrameBuffer::save_png` 现在需要 engine 的 `image` feature：

```toml
dotzuki-engine = { version = "0.8.0", features = ["image"] }
```

`dotzuki-engine-script` 的默认配置仍然包含 Boa。关闭默认 feature 后继续使用
`ScriptEngine`、`ScriptApiRegistrar` 或其他依赖 Boa 的导出时，必须启用
`script-boa`：

```toml
dotzuki-engine-script = { version = "0.8.0", default-features = false, features = ["script-boa"] }
```

`dotzuki_renderer::mon_icon` 现在归入 renderer 的资源加载边界。
仅使用 framebuffer 但需要该模块的消费方必须启用 `resource`：

```toml
dotzuki-renderer = { version = "0.8.0", default-features = false, features = ["resource"] }
```

## 迁移公开 hash map 值

公开的 engine 与 DSL 结构现在使用确定性且兼容 `no_std` 的 map 和 set alias。
传入这些 API 的 `std::collections` 值需要替换为所属 crate 导出的 alias：

```rust
use dotzuki_engine::hash::HashMap;

let mut flags = HashMap::default();
flags.insert("opened_gate".to_owned(), true);
```

DSL AST 值使用 `dotzuki_engine_dsl::hash::{HashMap, HashSet}`。
拥有旧 map 的所有权时，可以通过 `into_iter().collect()` 转换。

## 处理 `return` 语句

`StoryStmt` 新增 `Return` variant。对该 enum 做穷尽匹配的消费方需要添加 match arm。
原生 interpreter 与生成的 JavaScript 都会在执行该 variant 时结束当前 storyline。
不要持久化或比较 `StoryStmt` 的数值转换结果：插入 `Return` 改变了后续 `Assign`
与 `Command` variant 的隐式 discriminant。

## 更新依赖 renderer 类型细节的代码

以下 `BattleEffects` 方法现在带有可推导的 const 存储参数，使其同时接受 packed 与
linear RGBA 索引 framebuffer：

- `apply_enemy_hud_shake`
- `apply_screen_effects`
- `render_objects`
- `draw_substitute`
- `draw_minimized`
- `draw_squished`
- `draw_mon_rows`

常规调用会推导该参数。使用 turbofish 显式传入泛型参数的调用需要包含新的 const
参数，或改为让编译器推导。

`dotzuki_renderer::tile::Tile` 现在按四字节对齐，使 GBA tile copy 路径能够执行
对齐的 word load。不要把 `Tile` 放进下游 `repr(packed)` 结构；请单独存储它，
或使用满足对齐要求的容器。

## 选择索引 framebuffer 存储

`IndexedFrameBuffer` 与 `RgbaIndexedFrameBuffer` 在所有目标上仍默认使用 packed
存储。现有 packed 存储代码可以继续使用 `packed()` 与 `packed_mut()`。

平台需要每个调色板索引一个字节、word alignment、`indices()` 或 `indices_mut()` 时，
使用 `LinearIndexedFrameBuffer` 或 `LinearRgbaIndexedFrameBuffer`。
GBA Mode 4 消费方应使用 linear alias，以便通过 DMA 提交：

```rust
use dotzuki_renderer::{LinearRgbaIndexedFrameBuffer, RenderConfig, Rgba};

let framebuffer = LinearRgbaIndexedFrameBuffer::new(
    RenderConfig::new(160, 144),
    Rgba::BLACK,
);
```

存储选择现在是类型的一部分，不会再随编译目标变化。
