# Migration Guide — v0.1.x → v0.5.4

How to move a game repository from the 0.1.x crates.io line to v0.5.4.

> - **Audience**: rust developers
> - **Type**: how-to
> - **Status**: active
> - **Last verified**: v0.5.4

v0.5.4 returns the workspace version to the v0.5.x tag series. The `v0.1.0`
release had reset the version line from the v0.5.x pre-release tags to 0.1.0;
the reset did not stick — the `v0.5.2` / `v0.5.3` tag pushes failed the
release workflows' tag↔version assertion while the workspace still read
0.1.1, so they published nothing. v0.5.4 aligns the workspace version with
the tag series again: one tag, `v0.5.4`, publishes every crate at 0.5.4.

The release is additive apart from the overworld NPC changes below.

## Breaking changes

### `NpcDefinition` / `NpcRuntimeState` gained `wander_axis`

Both structs carry a new public field
`wander_axis: NpcWanderAxis` (`Any` / `Vertical` / `Horizontal` — the classic
movement byte 2), so struct literals fail to compile until you add the field.
`NpcDefinition::new_with_axis`
(`crates/dotzuki-engine/src/overworld/types.rs`) constructs one without a
struct literal.

Wander NPCs also lost their radial leash: a random walker walks its allowed
axis until blocked, and NPC walk cadence is 16 frames per tile — half the
player's speed.

### `advance_step` no longer ticks repel

`overworld` step advancement used to decrement `repel_steps`; the counter now
belongs to the game's encounter-check gate. If your game relied on the
engine-side tick, call the new `tick_repel_step` helper once per step from
your encounter check instead
(`crates/dotzuki-engine/src/overworld/player_movement.rs`).

## New systems worth adopting

Everything below is new API, documented under
[reference](../../reference/rustdoc.md):

- Shops: `items::mart` ([shops](../../reference/shops.md))
- Overworld presentation animations ([reference](../../reference/overworld-presentation.md))
- Link play: engine codec + TCP / BroadcastChannel transports + the session
  router ([reference](../../reference/link-play.md))
- Debug server: TCP JSON-line endpoint for tests and tooling
  ([reference](../../reference/debug-server.md))
- Audio runtime: `AudioManager` + the `cpal` / `web-audio` output features
  ([reference](../../reference/audio-runtime.md))
- Renderer resource pipeline: PNG → tile data, `AssetRoot`,
  `ResourceManager` ([reference](../../reference/resource-manager.md))
- DSL runtime loading with hot reload
  ([reference](../../reference/dsl/runtime-loading.md))
- Web game shell ([reference](../../reference/game-shell.md))
- `dotzuki-ui`: games can inject custom GB tile glyphs into
  `FrameBufferPainter`

## Steps

1. Bump every `dotzuki-*` dependency to `= "0.5.4"` (registry) or
   `tag = "v0.5.4"` (git).
2. Fix `NpcDefinition` / `NpcRuntimeState` literals (add `wander_axis`) and
   move any repel ticking to `tick_repel_step` at your encounter gate.
3. `cargo update && cargo build` — everything else is additive.
4. Zero-Rust projects contain no Cargo manifests; nothing changes there.
