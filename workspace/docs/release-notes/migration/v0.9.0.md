# Migrating to v0.9.0

> - **Audience**: rust developers, game authors
> - **Type**: how-to
> - **Status**: active
> - **Last verified**: v0.9.0

Update consumers from v0.8.2 and replace removed UI APIs before rebuilding.
Before you start, read the [changelog](../changelog.md) for the release scope.

## Update dependencies and toolchain

Use Rust 1.88 or newer and update every `dotzuki-*` dependency together.
For registry dependencies, set each version to `0.9.0`; for git dependencies,
set each tag to `v0.9.0`. Refresh the consumer lockfile after editing the manifest.

## Replace deprecated UI calls

Replace `DialogConfig`, `FlexMenuConfig`, and `YesNoConfig` with
`dotzuki_engine::menu::MenuConfig`. Replace `draw_dialog_legacy`,
`draw_flex_menu_legacy`, and `draw_yes_no_legacy` with the corresponding
`draw_dialog`, `draw_flex_menu`, and `draw_yes_no` calls using `MenuConfig`
slices and `Ui`. Remove imports of the old flex-menu `EdgeInsets`, `Justify`,
and `SizeMode` types.

Handle the `Result` from static layout `Context::set`. An exhausted context
returns `ContextCapacityError`; increase its const capacity or report the
binding failure. Updating an existing binding reuses its slot.

## Replace actor patches and input workarounds

Use `OverworldActor::set_movement_speeds` for game-specific walking/running
cadence and `set_step_speed` for a temporary override. Speeds must be positive
and finite. An override of `None` restores the configured pair; changes affect
the next update even during an active step. Set speeds while idle when timing
must remain fixed for the entire step. The default pair remains 2/4 pixels per
update, and animation cadence is unchanged.

Use `OverworldActor::nudge` for caller-driven pixel offsets. It bypasses
collision and preserves the target tile, facing, and walking state. An active
step continues toward its original tile target on the next update.

The Web game shell now uses `BufferedInput` for browser and native fallback
windows. Remove duplicate consumer key listeners that implemented short-tap
buffering. Custom loops can collect events through `set_button`, call
`next_frame` once per simulation update, and call `clear` on focus loss.
Multiple taps between updates coalesce; this is not an event replay queue.

## Refresh exported mobile hosts

Re-export Android and Harmony hosts to obtain the runner lifetime fixes.
Existing autotile connection sets without a `mode` retain cardinal behavior.
The native scenery editor preserves the generic runner's rendering behavior.
