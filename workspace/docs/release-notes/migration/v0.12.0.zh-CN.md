# 迁移至 v0.12.0

> 本文是 `release-notes/migration/v0.12.0.md` 的中文翻译，同步至引擎版本 v0.12.0（源文档 commit 3030dd484e28cfd7c128e8451e72b73d36913006）。
> 内容以英文源为准。

> - **Audience**: rust developers, game authors
> - **Type**: how-to
> - **Status**: active
> - **Last verified**: v0.12.0

本指南说明如何更新自定义战斗宿主，并为导出的游戏配套分发兼容的播放器。
开始前请阅读[变更日志](../changelog.zh-CN.md)。从早于 v0.11.0 的版本升级时，
还请阅读[上一版迁移指南](v0.11.0.zh-CN.md)。

## 更新战斗宿主

将所有 dotzuki 依赖一起更新到 registry 版本 `0.12.0` 或 git 标签 `v0.12.0`。
刷新游戏的锁文件，以及各个独立目标的锁文件。

如果宿主直接构造[战斗钩子状态](../../reference/battle-rules.zh-CN.md#零-rust-运行器中的规则所有权)，
用 `BattleRules::compile(&ruleset, resource)` 编译项目定义。用 `Arc` 包装结果，
每次遭遇时克隆该引用，传给 `HookState::new(rules, &player, &enemy)`。
通过 `state.rules.compiled().hooks` 和 `state.rules.compiled().stats` 读取编译后的钩子与属性名。
通过 `state.rules.move_records`、`state.rules.status_names` 和 `state.rules.has_resource`
访问招式记录、状态名和资源设置。调用 `BattleSetup::from_project` 的宿主会自动共享定义。

## 重新构建播放器和导出包

对需要分发[预编译场景数据](../../reference/glossary.md#compiled-scene-assets)的每个目标
重新运行 `dotzuki export`。配套使用相同版本的 Web 运行器包或原生播放器，即可按需加载原生函数。
旧版播放器会读取随包源码。从磁盘打开的项目仍支持源码热重载。

如果[移动外壳](../../explanation/mobile-architecture.zh-CN.md)调用
`dotzuki_mobile_copy_frame_update`，请重新构建 Rust 运行库归档，并使用配套的 C 头文件链接。
该符号在 ABI v1 中可选。读取完整帧快照的宿主可以继续调用 `dotzuki_mobile_copy_frame`。

## 验证升级

打开已有存档，重返一张地图，并完成一场战斗。如果游戏使用自定义钩子宿主，
再开始一次遭遇，确认 HP 和易变状态从本次遭遇自身的状态开始。
用计划分发的播放器运行已导出的场景。如果游戏在 `@run` 中使用原生 JavaScript 代码，也请运行对应剧情线。
