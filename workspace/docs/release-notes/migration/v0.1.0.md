# Migration Guide — v0.5.x (pre-release) → v0.1.0

How to move a game repository from the v0.5.x git-tag era to the published
v0.1.0 workspace.

> - **Audience**: rust developers
> - **Type**: how-to
> - **Status**: active
> - **Last verified**: v0.1.0

v0.1.0 is the first crates.io release of the engine workspace. It renames
the version line (the pre-release tags were `v0.5.0` / `v0.5.1`; the
published workspace version is `0.1.0`) and ships the release pipeline —
and nothing else. The code at tag `v0.1.0` is one commit past `v0.5.1`: the
version strings in `workspace/crates/*/Cargo.toml`, the publish script
(`workspace/scripts/publish-crates.sh`) and the tag-driven release
workflow. No engine API changed in that jump, so this guide has no breaking
changes to describe; it documents the two things that DID change: where the
crates come from and what the version numbers mean.

## Before (v0.5.x era)

Games consumed the engine as Cargo **git dependencies** pinned to a
pre-release tag:

```toml
[dependencies]
dotzuki-engine = { git = "https://github.com/liuyanghejerry/dotzuki", tag = "v0.5.1" }
dotzuki-rules  = { git = "https://github.com/liuyanghejerry/dotzuki", tag = "v0.5.1" }
```

## After (v0.1.0)

Same crates, published to crates.io. Both forms stay supported:

```toml
[dependencies]
# Registry (preferred): one shared version for every dotzuki-* crate.
dotzuki-engine = "0.1.0"
dotzuki-rules  = "0.1.0"

# Or keep pinning a git tag.
dotzuki-engine = { git = "https://github.com/liuyanghejerry/dotzuki", tag = "v0.1.0" }
dotzuki-rules  = { git = "https://github.com/liuyanghejerry/dotzuki", tag = "v0.1.0" }
```

### Steps

1. Replace every `tag = "v0.5.x"` with `tag = "v0.1.0"`, or switch the
   dependency to the registry form `dotzuki-<crate> = "0.1.0"`.
2. If your game vendors its own copy of the workspace, bump every internal
   `dotzuki-*` path dependency's `version` string to `0.1.0` — crates.io
   resolves path deps through the registry, and mismatched versions fail
   the release gate.
3. `cargo update && cargo build` — a clean build is the whole migration.
4. If you use `dotzuki new` projects (zero-Rust games), nothing changes:
   those projects contain no Cargo manifests.

## Version policy from v0.1.0 on

- One shared version: every `dotzuki-*` crate inherits the workspace
  version; one bump releases them all.
- A tag `vX.Y.Z` publishes every crate at `X.Y.Z` (the release workflow
  runs `workspace/scripts/publish-crates.sh`).
- Each release ships a migration guide in this directory; the changelog
  links it from the release's entry.
