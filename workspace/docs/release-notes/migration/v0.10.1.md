# Migrating to v0.10.1

> - **Audience**: rust developers
> - **Type**: how-to
> - **Status**: active
> - **Last verified**: v0.10.1

Update dependencies and remove downstream copies of the DSL no_std integer-check fix.
Before you start, read the [changelog](../changelog.md) and, if upgrading from an older
release, the [v0.10.0 migration guide](v0.10.0.md).

## Update dependencies

Update all dotzuki dependencies together to registry version `0.10.1` or git tag `v0.10.1`.
Keep the main workspace and any standalone bare-metal manifests on the same release,
and refresh their lockfiles. The minimum Rust version remains 1.88.

Remove Cargo patch entries that redirect `dotzuki-engine-dsl` to a local copy containing
only the integer-check workaround. Delete that copy after confirming no other changes
remain in it. Keep unrelated dependency patches required by your target.

## Preserve stationary NPC behavior

Consumers of the branch-only `update_npc_movement_with_policy_and_stationary` API can now
use that API from the release. Retain the game's callback and chosen `NpcWanderPolicy`.
The callback receives visible, idle stationary NPCs in the existing movement traversal;
walking and scripted NPCs stay outside the callback. Existing movement entry points need
no changes and keep their stationary-NPC behavior.

## Verify the upgrade

Compile your no_std target with the updated lockfile and run your scene-command tests.
Valid u8, u16, and i16 boundaries remain accepted; fractional, non-finite, and out-of-range
arguments remain rejected. Check stationary facing, wander delays, scripted movement,
and NPC collisions in consumers that use the movement callback.

The engine CI checks the audio and DSL libraries on `thumbv4t-none-eabi` with default
features disabled. Host-only DSL compiler binaries are excluded from this bare-metal check.
