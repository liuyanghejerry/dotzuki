## 更新依赖

一起更新所有 dotzuki 依赖，使用 registry 版本 `0.10.0` 或 git tag `v0.10.0`。
固定在 `92ba95f` 的消费者可在测试游戏后，将分支 revision 换成正式发布标签。
最低 Rust 版本仍为 1.88。
跳过 v0.9.0 的消费者还需按其[迁移指南](v0.9.0.zh-CN.md)处理已移除的 UI API。

## 更新 NPC 状态适配器

`NpcRuntimeState::delay_counter` 现在使用 `u16`。
用 `u16::from(value)` 扩宽带类型的 `u8` 赋值；写入存档时保留直至 256 的值。
不要将该字段截断回 `u8`。审查二进制序列化布局；
若存档以固定宽度保存该字段，应升级存档格式版本。

已有的 `update_npc_movement` 入口保留默认策略。
使用 `update_npc_movement_with_policy` 并传入 `NpcWanderPolicy::Classic`，
可启用四个等宽方向区间、受限轴方向映射，以及将零随机延迟解释为 256 帧的行为。
由消费游戏选择策略。

## 保留战斗行动时序

`StackDriver::execute_turn_logged_with_before_action` 在回合排序之后、
每个行动者的强制行动解析之前调用消费方回调。
回调可以检查首个行动者留下的状态，并替换当前行动、状态或效果。
被取消的第二个行动者不会触发回调。已有回合入口不使用回调。

`EffectProvider::resolved_move` 默认返回选定招式。
当成功通过 `BeforeMove` 状态门后需要解析调用招式时，可覆盖该方法。
排序仍使用选定行动；后续招式流程及日志条目使用解析后的招式。
状态门仅运行一次。训练师决策和游戏专用的招式调用规则保留在消费者中。

## 接入裸机音频

在裸机目标上关闭默认 feature 构建 `dotzuki-audio`。
`Apu::set_register_sink` 为宿主的 PSG 适配器安装可选寄存器写入回调。
接受的寄存器写入仍会更新软件 APU。
消费者负责硬件地址转换和输出时序。

稀疏音轨槽位现在保留其声道位置。移除压缩或重新索引这些槽位的临时处理。
在每个受支持后端上测试音乐、音效结束、音量、声像和滑音；
寄存器级测试不能替代硬件试听。

## 验证游戏行为

检查两个行动者执行前的训练师道具/换人决策、强制行动、首个行动者造成 KO、
调用招式、受限轴 NPC 游走、零延迟倒计时和向外螺旋转场。
已使用分支钩子的游戏在切换依赖时，应保留现有回调及显式经典策略。
