🎨 GUI DSL + 📜 Scene DSL

两套 DSL，各司其职

本项目包含两套独立的声明式 DSL： GUI DSL 负责排版布局（.gui 文件 → JSON）， Scene DSL 负责对话脚本（.scene 文件 → JavaScript）。 它们语法不同、编译产物不同、职责完全不同，在运行时配合呈现完整的游戏体验。

📥 输入 (.gui)
screen Dialog { panel { rect = {tx: 0, ty: 12, tw: 20, th: 6} text("{text}") { wrap = "word" } } }
📤 中间输出 (JSON)
{"schema_version": 2, "screen": "Dialog", "elements": [{ "type": "border", "rect": {"tx":0,"ty":12, "tw":20,"th":6}, "children": [{ "type": "text", "value": "{text}", "wrap": "word" }] }] }
📦 最终产物 (Rust)
// build.rs 生成: ui_layouts_gen.rs pub fn get_screen_v2_json( screen: &str ) -> Option<&static str> { match screen { "main" => Some(r#"{...JSON嵌入在此...}"#), "dialog" => Some(r#"{...}"#), _ => None, } } // 运行时 serde 反序列化 let json = get_screen_v2_json("dialog"); let layout: ScreenLayout = serde_json::from_str(json);
关键转换： screen → JSON 根对象；panel → {"type": "border"} 含 children 数组； text("内容") → {"type": "text", "value": "内容"}； rect = {tx, ty, tw, th} → 瓦片坐标对象； @t("en","中文") → {"en": "...", "zh": "..."} 多语言值。

JSON 到 Rust：build.rs 中的 generate_ui_layouts() 将编译后的 JSON 直接嵌入生成的 ui_layouts_gen.rs 文件，以 &'static str 形式存在。 schema.rs 通过 include!() 包含该文件。运行时，菜单代码调用 get_screen_v2_json() 获取 JSON 字符串，用 serde_json::from_str() 反序列化为 ScreenLayout 结构体（定义在 dotzuki-renderer/layout_engine/types.rs）。 v1 路径更激进：build.rs 直接生成具名 Rust 结构体（如 DialogDefaultLayout），编译期零成本。
G1
瓦片坐标系统 .gui
一切布局的基石 — 20×18 网格 + rect 定位
dialog.gui
// 坐标系: 20 列 × 18 行, 每格 = 8×8 像素 // tx = 列, ty = 行, tw = 宽, th = 高 (单位: 瓦片) screen Dialog { panel { rect = {tx: 0, ty: 12, tw: 20, th: 6} style = "default" text("{text}") { rect = {tx: 1, ty: 13, tw: 18, th: 4} wrap = "word" } } }
📺 渲染预览 — 瓦片网格 + 对话框定位
GUI DSL 的核心坐标系统：所有组件通过 rect 属性在 20×18 网格上做绝对定位。
rect = {tx: 0, ty: 12, tw: 20, th: 6}
tx/ty = 左上角瓦片坐标，tw/th = 宽/高（瓦片数）。 每个瓦片对应 8×8 像素，总分辨率 160×144。对话框固定在底部 6 行，文字向内缩进 1 格。
G2
组件系统 .gui
16 种内置组件 + 自定义组件声明
所有组件类型
// ── 容器类 ── panel GB 风格边框的面板 (style="default") container 无边框容器, 可做 clip // ── 内容类 ── text() 文本 (wrap/align/color/font/line_spacing) button() 按钮 (on_click 绑定) tile(n) 单个 GB 瓦片 (flip_x/y, palette) image() 图像 (slice 九宫格) divider 分隔线 (水平/垂直, repeat) // ── 列表类 ── list 滚动列表 (source, cursor, max_visible) flex_list 弹性多列列表 (item_layout) // ── 光标 ── cursor 选择指示 ▶︎ (1-D 列表 / 2-D 网格) // ── 图元 ── bracket 括号框 pixel_rect 像素矩形 // ── 输入 ── input 输入框 dropdown 下拉选择器 // ── 自定义 ── component 声明自定义组件 (如 hp_bar)
📺 渲染预览 — 多组件组合
16 种内置组件，分 5 大类。panel 是带 GB 边框的面板， container 是无边框容器。list + cursor 实现菜单列表。component 声明让游戏侧注册自定义元素（如 HP 条）， 编译器会校验 prop 类型和必填项。
G3
文本排版属性 .gui
换行、对齐、颜色、行间距、字体、模板变量
text 组件完整属性
text("显示内容") { rect = {tx: 0, ty: 0, tw: 20, th: 4} align = "center" // left | center | right color = "Black" // Black | DarkGray | LightGray | White | #rrggbb font = "pk_glyph" // 字体名称 wrap = "word" // 单词换行 line_spacing = 1 // 行间距 (瓦片数) } // \n 手动换行 + wrap 自动折行 text("Line 1\nLine 2\nLine 3") { rect = {tx: 1, ty: 5, tw: 18, th: 4} wrap = "word" } // 模板变量: {variable} 运行时绑定 text("{player_name}") { rect = {tx: 5, ty: 2, tw: 7, th: 1} color = "White" }
📺 渲染预览 — 文字排版
text 是最常用的组件。支持 4 阶灰度颜色 （Black/DarkGray/LightGray/White，对应 GB 的调色板）、 三种对齐方式、单词换行 wrap = "word"、 行间距 line_spacing、以及 {变量} 运行时数据绑定。

编译原理：GUI DSL 编译器将每个 text(...) 解析为 AST 的 UiComponent::Text 节点，所有属性（wrap, align, color 等） 抽取到 ComponentProps 结构体。Codegen 遍历 AST，将每个组件输出为 {"type": "text", "value": "...", "wrap": "word", ...} JSON 对象。 panel 中的子组件递归输出为 "children": [...] 嵌套数组。

双语文本 i18n .gui
@t("en", "中文") — 同一布局服务多语言
mart_buy.gui
// @t("英文", "中文") 编译为 {"en":"...", "zh":"..."} screen MartBuy { panel { rect = {tx: 0, ty: 0, tw: 18, th: 15} style = "default" } flex_list("{shop_items}") { rect = {tx: 1, ty: 1, tw: 16, th: 13} item_layout = [ {field: "name", width: 13, align: "left"} {field: "price", width: 3, align: "right", prefix: "$"} ] cursor = {tile: 223, position: "left"} } // 双语 + 模板变量混用 text(@t("MONEY ${balance}", "金钱 ${balance}")) { rect = {tx: 1, ty: 16, tw: 16, th: 1} } }
📺 渲染预览 — English
@t("English", "中文") 是 GUI DSL 的内联国际化语法。 编译为语言索引对象：{"en": "MONEY $500", "zh": "金钱 $500"}。 渲染器根据当前语言自动选择，未提供的语言回退到英文。 支持与 {模板变量} 混用。35 个 .gui 文件中多个已采用此模式。

列表 & 光标系统 .gui
list / flex_list 菜单 + cursor 1-D / 2-D 网格

// ── list: 主菜单滚动列表 ── screen Main { panel { rect = {tx: 0, ty: 0, tw: 13, th: 9} style = "default" } list { rect = {tx: 1, ty: 2, tw: 11, th: 6} source = "{items}" item_template = {height: 1, gap: 1} cursor = {tile: 223} max_visible = 3 } } // ── cursor: 2×2 网格 (战斗菜单) ── cursor { rect = {tx: 9, ty: 14, tw: 1, th: 1} col_step = 6 row_step = 2 col = "{bcol}" row = "{brow}" }

@theme 颜色令牌 + @style 复用（含继承链）

📤 中间输出 (JS)
async function storyline_main() { const __st = runtime; const __s = __st.statements; // @storyline("talkOak") __s["talkOak"] = async () => { await game.showText("OAK: Hey! Wait!"); }; }
📦 最终产物 (Rust 嵌入)
// dotzuki-engine-dsl/build.rs 生成 // embedded_scenes.rs static SCENE_0: &str = include_str!(r"OUT_DIR/PalletTown.js"); static SCENE_1: &str = include_str!(r"OUT_DIR/OaksLab.js"); pub fn load_embedded_scenes( reg: &mut impl DslSceneRegistrar ) { reg.register_scene( "PalletTown", SCENE_0); reg.register_scene( "OaksLab", SCENE_1); } // 运行时: Boa 引擎执行 let js = load_embedded_scenes(&mut registrar); let result = engine.evaluate(js);
关键转换： @speaker("Name") { "text" } → await game.showText("Name: text")（自动加名字前缀）； @speaker("") { "text" } → await game.showText("text")（旁白，无前缀）； @choice { @option("A"){...} @option("B"){...} } → const c = await game.showChoice(["A","B"]); if (c===0){...} else {...}； @if (getFlag("X")) { ... } → if (game.getFlag("X")) { ... }（函数自动加 game. 前缀）； giveItem("X",1) → await game["giveItem"]("X",1)（所有命令自动 await 并走 game[name]() 动态分发）。 字符串中的 {variable} → JS 模板字面量 ${...}。

JS 到 Rust：dotzuki-engine-dsl/build.rs 将编译后的 JS 写入 OUT_DIR/， 生成 embedded_scenes.rs 通过 include_str!() 嵌入每个 JS 文件。 运行时，loader.rs 调用 load_embedded_scenes() 将 JS 源码注册到场景系统中， 当玩家触发对话时，Boa JS 引擎执行对应场景的 JS 函数。

S2
触发器系统 .scene
@trigger — 故事线绑定到 NPC / 路牌 / 坐标
三种触发类型
// ── NPC 对话触发 ── @trigger(map = "PalletTown", npc = 1, toggle = "PALLET_TOWN_OBJ_1", hidden = true) // ── 路牌触发 ── @trigger(map = "PalletTown", sign = 1) // ── 坐标触发 (玩家踩到某格) ── @trigger(map = "PalletTown", name = "northExit1") // ── 一条故事线共享多个触发 ── @storyline("talkPokedex") { @trigger(map="OaksLab", npc=6, toggle="OAKS_LAB_OBJ_6") @trigger(map="OaksLab", npc=7, toggle="OAKS_LAB_OBJ_7") @speaker("") { "It's encyclopedia-\nlike, but blank!" } }
📺 渲染预览 — 触发 NPC 对话
@trigger 将故事线绑定到游戏世界的具体对象。 支持 3 种触发类型：npc（与 NPC 对话）、 sign（查看路牌）、name（坐标触发）。 一条故事线可以有多个 @trigger，绑定到不同对象但共享同一段对话。 toggle 控制 NPC 显隐，hidden 表示初始隐藏。
S3
说话人系统 .scene
@speaker — 角色对话 vs 旁白形式，多段连珠
script.scene — 对话写法
// ── 带名字的说话人 ── // 编译: await game.showText("OAK: Hey! Wait!") @speaker("OAK") { "Hey! Wait!\nDon't go out!" } // ── 旁白形式 (空名字 = 无前缀) ── // 编译: await game.showText("It's a signpost.") // 绝不带 "System: " 前缀! @speaker("") { "It's a signpost.\nPALLET TOWN" } // ── 多段对话连续 ── @speaker("OAK") { "Hello!" } @speaker("") { ": Hey!" } @speaker("OAK") { "Be patient!" } // ── 剧情台词 @say: 剧情中 NPC 交错连续说话 ── // 编译: await game.showText("OAK: Follow me!") @say("OAK") { "Follow me!" } // ── @t 双语对话 ── @speaker("OAK") { @t("Hello!", "你好！") }
📺 渲染预览 — 说话人 + 旁白
@speaker("名字") 在文本前自动添加 "名字: " 前缀。 @speaker("")（空字符串）是旁白形式，编译为纯 game.showText()，不加任何前缀。 这曾是一个历史坑点——如果占位符用了 "System"，"System: " 前缀会泄漏到文本框。本项目有专门的 回归测试 test_speaker_empty_name_no_prefix 防止复现。

语义固定：@speaker 只表达 玩家主动对话（NPC talk 触发、按 A 推进）； 剧情中 NPC 交错连续说话用 @say("名字")。 两者编译产物相同（game.showText），区别在语义——剧情台词不会 被误写成主动对话,反之亦然。

编译原理：Parser 将 @speaker 解析为 StoryStmt::Speaker { name: Expression, texts: Vec<LocalizedText> } 节点 （@say 为 StoryStmt::Say）。 Codegen 中的 compile_speaker() 函数（js_storyline.rs，约 70 行） 拼接名字和正文：名字非空时输出 await game.showText("Name: text")， 空名字时直接输出 await game.showText("text")。 多条文本用 \n 连接，@t 双语文本调用 game.t()。
S4
选择 & 条件分支 .scene
@choice/@option + @if/@else — 剧情分叉
script.scene — 分支逻辑
// ── @choice: 对话选项 ── // 编译为: const choice = await game.showChoice(["YES","NO"]) @choice { @option("YES") { givePokemon("CHARMANDER", 5) setFlag("EVENT_GOT_STARTER") } @option("NO") { } } // ── @if/@else: 基于游戏状态的条件对话 ── @if (getFlag("EVENT_GOT_STARTER")) { @speaker("OAK") { "Raise your POKeMON!" } } @else @if (hasItem("OAKS_PARCEL")) { @speaker("OAK") { "You have something\nfor me?" } takeItem("OAKS_PARCEL", 1) } @else { @speaker("OAK") { "Be patient, !" } }
📺 渲染预览 — 选择分支
@choice + @option 编译为 game.showChoice() + if/else 链。 每个选项后可以跟任意复杂的嵌套逻辑。

编译原理：Parser 将 @choice 解析为 StoryStmt::Choice { options: Vec<ChoiceOption> }。 每个 @option 的 label 和 body 分别存储。Codegen 输出：
const __choice = await game.showChoice(["YES","NO"]);
if (__choice === 0) { /* YES 分支 */ } else { /* NO 分支 */ }
@if/@else 根据游戏状态（Flag、物品、变量比较）选择不同对话。 同一个 NPC 随剧情推进会说出完全不同的话。条件支持 getFlag()、 hasItem()、比较运算、&& || ! 逻辑组合。所有函数调用自动添加 game. 前缀。 Parser 将 @if 解析为 StoryStmt::If { condition, then_branch, else_branch }， Codegen 递归编译条件表达式和分支语句体。
