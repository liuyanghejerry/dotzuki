dotzuki CLI 参考

  • Audience: game authors, CI
  • Type: reference
  • Status: active
  • Last verified: v0.6.0

用于生成骨架、校验和运行零 Rust 游戏项目的每个 dotzuki 子命令、flag 和退出 码。

dotzuki 二进制（crates/dotzuki-cli）生成骨架、校验并运行零 Rust 游戏 项目——包含 DSL、数据和资产的普通目录，外加一份 .dotzuki-editor.json 项目清单（见项目清单）。

从 workspace 根目录构建：

cd workspace
cargo build --release --bin dotzuki

产物是 target/release/dotzuki。所有命令都接收一个项目路径；定义项目布局的 是项目清单，不是 CLI。

子命令

命令用途
dotzuki new <name>生成一个新的游戏项目骨架（布局与编辑器的空模板一致）
dotzuki check <dir>编译项目中的每个 DSL 文件并报告诊断信息；出错时退出码为 1。有 battle 区块时还会校验它
dotzuki run <dir>启动项目并在窗口中游玩（或为 CI/截图以无头模式运行）
dotzuki export --web <dir>把项目导出为静态网站
dotzuki export --native <dir>把项目导出为原生应用目录
dotzuki export --harmony <dir>导出鸿蒙 DevEco Studio 工程（移动运行时 + 游戏 pack）

dotzuki new <name>

生成一个新的项目骨架。name 必须是 slug：[a-z0-9][a-z0-9-]*。

Flag默认值含义
--dir <parent>当前目录新项目创建于其中的父目录
--title <name>该 slug存入项目清单根 name 字段的显示名
--template <name>empty项目模板：empty（编辑器的空布局）或 your-first-game（教程中的教程项目，内嵌于 CLI）

生成的布局：.dotzuki-editor.json + data/（maps、tiles、 stories/characters/quests/arcs）、gfx/、assets/scenes/main.scene、README ——编辑器的七个活动（maps / scripts / play / data / story / assets / tiles）。 --template your-first-game 改为写出完整教程项目——城镇、空地、脚本战斗、 随机遇敌与存档——并把项目名代入其清单。

dotzuki new my-game --dir ~/projects --title "My Game"
dotzuki new my-game --dir ~/projects --template your-first-game
cd ~/projects/my-game

dotzuki check <dir>

在内存中编译所有发现的 DSL 文件（.scene / .gui / .theme / .style）并 报告诊断信息；任何文件失败即退出码非零。项目清单带 battle 区块时还会校验：

  • 引用的表 id 存在于 data 活动中；
  • stats / skills / items / encounters 字段名存在于表 schema 中；
  • rules 文件能解析并通过 validate_ruleset（未知的事件、op、属性、类型和 资源都是加载时错误）。
dotzuki check .

dotzuki run <dir>

启动项目。默认为一个 320×240（可缩放）的窗口游戏循环。

Flag默认值含义
--map <id>项目清单 game.entryMap出生所在的地图（覆盖项目清单）
--lang <en|zh>enUI / 脚本语言（@t 双语文本据此选择）
--headlessoff无窗口运行——用于 smoke 测试和截图
--frames <n>120无头模式：要模拟的帧数
--screenshot <file.png>—无头模式：把最后一帧导出为 PNG
--saveoff无头模式：也写入存档文件（窗口模式运行总是存档）
--save-file <path><project>/.dotzuki-save.json存档文件位置
--freshoff忽略已有存档文件，从头开始
--watchoff文件变化时热重载场景和当前地图。仅窗口模式——与 --headless 一起时被忽略
--scale <n>3窗口缩放倍率

示例：

# Play a project
dotzuki run .

# CI smoke test: boot 60 frames headless, no window, no save
dotzuki run . --headless --frames 60

# Headless screenshot for previews
dotzuki run . --headless --map TownSquare --screenshot shot.png

# Iterate with hot reload
dotzuki run . --watch

dotzuki export --web <dir>

把项目打包为可在现代浏览器中运行的静态网站。它与编辑器 Play 活动使用 相同的 WasmRunner（dotzuki-runner-web）启动路径，因此导出的游戏与编辑器内 试玩表现一致。

Flag默认值含义
--out <dir><project>/dist/web输出目录（pack 会排除 dist，所以重复导出不会把上次产物打包进去）
--runner-pkg <dir>workspace pkg使用预构建的 dotzuki-runner-web wasm package 目录（不需要 wasm-pack）
--rebuild-runneroff即使已有预构建产物，也用 wasm-pack 重新构建 runner wasm package
--save-key <key>dotzuki-save:<title>player 页面保存存档所用的 localStorage key；嵌入导出物的宿主可固定自己的 key，以保留已有玩家存档
--lang <en|zh>enplayer 页面的 UI 语言（加载、状态和提示文本）
--forceoff即使校验报告诊断信息也导出

导出前会运行与 dotzuki check 相同的诊断；除非传入 --force，否则任何诊断 都会中止导出。输出目录包含：

dist/web/
├── index.html                      # player 页面：canvas、键盘、WebAudio、localStorage 存档
├── game.dzpk                       # 二进制游戏 pack：header + JSON index + 原始文件字节
└── wasm/
    ├── dotzuki_runner_web.js       # wasm-pack glue
    └── dotzuki_runner_web_bg.wasm  # runner 本体

game.dzpk 是所有导出目标共用的二进制 pack，由 dotzuki-runner 的 pack 模块 定义。它包含 12 字节 header（magic DZPK、u32 格式版本、u32 index 长度）、 JSON index { dotzuki: {tool, version, exportedAt}, files: { <path>: {offset, size} } }， 然后依次拼接每个文件的原始字节。原始字节避免了 base64 约 33% 的体积膨胀和 启动时解码，尤其适合包含实际 tileset 与音频的项目。旧版 CLI 导出的是 base64 game.bundle.json，当前 player 仍可启动该格式。

Pack 规则与编辑器的 play bundle 相同：排除 node_modules、.git、target、 dist、点目录、点文件和 *.bak，但始终包含 .dotzuki-editor.json。单文件上限 16 MB，未压缩总大小上限 64 MB。dotzuki.version 记录执行导出的 CLI 版本，仅供 参考，运行时不会强制校验。

Runner wasm package 按以下顺序解析：--runner-pkg → 预构建的 workspace/crates/dotzuki-runner-web/pkg → 使用 wasm-pack build --target web --release --features modern-audio 构建。后两种方式 要求 dotzuki 源码 checkout；在仓库外通过 cargo install 安装的 CLI 必须传入 --runner-pkg。

dotzuki export --web . --out dist/web
python3 -m http.server --directory dist/web   # 在 http://localhost:8000 游玩

dotzuki export --native <dir>

把项目打包为原生应用目录：通用的 dotzuki-player 二进制文件 （dotzuki-runner 的 bin target），以及 web 导出使用的同一个 game.dzpk pack。 Player 通过与 dotzuki run 相同的 RunnerGame 和窗口循环启动可执行文件旁的 pack，并把存档写到 pack 旁的 .dotzuki-save.json。

Flag默认值含义
--out <dir><project>/dist/native输出目录（pack 会排除 dist，所以重复导出不会把上次产物打包进去）
--player-bin <path>cargo build使用预构建的 dotzuki-player，不再执行构建
--forceoff即使校验报告诊断信息也导出

诊断门禁和 pack 规则与 --web 相同。输出目录包含：

dist/native/
├── <project-dir-name>[.exe]   # player 二进制文件，以项目目录名重命名
└── game.dzpk                  # 二进制游戏 pack，与 web 导出的文件相同

Player 二进制文件按以下顺序解析：--player-bin → 在源码 workspace 中执行 cargo build --release -p dotzuki-runner --bin dotzuki-player。后者使用增量构建， 所以重复导出成本较低。构建要求 dotzuki 源码 checkout；在仓库外通过 cargo install 安装的 CLI 必须传入 --player-bin。构建只面向宿主平台；要 发布到其他操作系统，请在该操作系统或对应的 CI runner 上导出。

dotzuki export --native . --out dist/native
dist/native/my-game            # 可双击启动的原生应用

随附的二进制文件也接受可选的 pack 路径（.dzpk 或旧版导出的 game.bundle.json），以及 --lang en|zh、--scale <n>、--fresh 和 --headless。无头模式还可使用 --frames 与 --screenshot，对导出产物执行 CI 冒烟测试：

dist/native/my-game --headless --frames 120 --screenshot boot.png

dotzuki export --harmony <dir>

把项目打包为鸿蒙 DevEco Studio 应用。应用通过 ABI 版本 1 使用 dotzuki-runner-mobile，并携带与其他导出 target 相同的 game.dzpk。

Flag默认值含义
--out <dir><project>/dist/harmonyDevEco Studio 工程输出目录
--mobile-lib <path>workspace target 或 DOTZUKI_MOBILE_LIB预构建的 arm64 鸿蒙 libdotzuki_runner_mobile.a
--forceoff即使校验报告诊断信息也导出

导出器不会调用鸿蒙 Rust 工具链。请先构建静态库，再传入路径：

dotzuki export --harmony . \
  --mobile-lib target/aarch64-unknown-linux-ohos/release/libdotzuki_runner_mobile.a

输出包括 ArkTS 生命周期和控制器、XComponent GLES3 renderer、OHAudio 输出、 Preferences 存档、C ABI header、静态库和 game.dzpk。参见 鸿蒙导出指南。

退出码

  • dotzuki check：0 = 所有 DSL 编译通过（且 battle 区块校验通过）；1 = 发现诊断信息。
  • dotzuki run：0 = 正常退出。
  • dotzuki export --web：0 = 已写出站点；1 = 校验失败（未传 --force）、项目超过 pack 限制，或没有可用的 runner wasm package。
  • dotzuki export --native：0 = 已写出应用目录；1 = 校验失败（未传 --force）、项目超过 pack 限制，或没有可用的 player 二进制文件。
  • dotzuki export --harmony：0 = 已写出 DevEco Studio 工程；1 = 校验失败、 项目超过 pack 限制，或移动运行时 library 不可用。

说明

  • 存档文件带版本号（.dotzuki-save.json）；--fresh 从头开始，不动该文件。
  • 无头模式运行会模拟完整的帧循环，包括场景 / 战斗分发，因此 --screenshot 的输出反映真实的渲染状态。
  • 编辑器的 Play 活动通过 WASM（dotzuki-runner-web）使用同一个运行器，而不 是这个 CLI。
