迁移指南 — v0.1.x → v0.5.4

如何把游戏仓库从 0.1.x crates.io 版本线迁移到 v0.5.4。

本文是 release-notes/migration/v0.5.4.md 的中文翻译，同步至引擎版本 v0.5.4（源文档 commit 3133fb419ae3bc6e5c08bbbcd43ac7fa0289e44f）。 内容以英文源为准；发现不一致请更新英文源再同步翻译。

  • Audience: rust developers
  • Type: how-to
  • Status: active
  • Last verified: v0.5.4

v0.5.4 让 workspace 版本回到 v0.5.x tag 序列。v0.1.0 曾把版本线从 v0.5.x 预发布 tag 重置为 0.1.0，但这次重置没有维持住——v0.5.2 / v0.5.3 两次 tag 推送时 workspace 版本仍是 0.1.1，触发了发布工作流的 tag↔version 断言失 败，没有发布任何内容。v0.5.4 让 workspace 版本与 tag 序列重新对齐：一个 v0.5.4 tag 把所有 crate 以 0.5.4 发布。

除下面的大地图 NPC 变更外，本 release 均为新增内容。

Breaking changes

NpcDefinition / NpcRuntimeState 新增 wander_axis

两个结构体都新增了公开字段 wander_axis: NpcWanderAxis（Any / Vertical / Horizontal——即经典的 movement byte 2），因此结构体字面量 在补上该字段之前无法编译。NpcDefinition::new_with_axis （crates/dotzuki-engine/src/overworld/types.rs）可以不写字面量直接构造。

Wander NPC 同时失去了半径束缚：随机行走的 NPC 会沿允许的轴向一直走到被阻挡 为止；NPC 走路节奏为每 tile 16 帧——玩家速度的一半。

advance_step 不再推进 repel

overworld 的步进过去会递减 repel_steps；该计数器现在归游戏自己的遇敌检查 门槛管理。如果你的游戏依赖引擎侧的推进，改为在遇敌检查里每步调用一次新的 tick_repel_step 辅助函数 （crates/dotzuki-engine/src/overworld/player_movement.rs）。

值得采用的新系统

以下全部是新增 API，文档见 reference：

  • 商店：items::mart（商店）
  • 大地图表现动画（参考）
  • 联机：引擎 codec + TCP / BroadcastChannel 传输 + 会话路由器 （参考）
  • 调试服务器：供测试与工具使用的 TCP JSON-line 端点 （参考）
  • 音频运行时：AudioManager + cpal / web-audio 输出 feature （参考）
  • 渲染器资源管线：PNG → tile 数据、AssetRoot、ResourceManager （参考）
  • 带热重载的 DSL 运行时加载 （参考）
  • Web 游戏外壳（参考）
  • dotzuki-ui：游戏可以向 FrameBufferPainter 注入自定义 GB tile 字形

步骤

  1. 把每个 dotzuki-* 依赖升到 = "0.5.4"（registry）或 tag = "v0.5.4"（git）。
  2. 修复 NpcDefinition / NpcRuntimeState 字面量（补 wander_axis），并把 repel 推进迁到遇敌门槛里的 tick_repel_step。
  3. cargo update && cargo build——其余全部是新增内容。
  4. 零 Rust 项目不含 Cargo 清单，无需任何改动。
