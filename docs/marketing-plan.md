# dotzuki-engine 对外宣传方案

> 版本:v2 · 目标:为 dotzuki-engine 的商业化销售建立对外传播体系
> 案例资产:pokered(复杂度证明)、wuxia(原创零代码工作流证明)
> v2 变更:商业模式确认为"开源引流 + 商业授权 + SaaS 定制";海外市场不做先验结论,改为国内主线 + 海外低成本探针,数据驱动决策。
> 拆分后注记(2026-08):pokered 与 wuxia 已迁出为独立仓库(无历史、本地起步),以 Cargo git 依赖(engine repo tag v0.1.0)消费引擎 crate。本方案中把 pokered/wuxia 作为"外部案例项目"表述;对外传播时如需展示,需先与两个独立仓库的维护方协调或使用脱敏截图。

## 0. 商业模式(已确认)

三层结构:

| 层 | 内容 | 收费方式 | 作用 |
|----|------|---------|------|
| **开源层** | dotzuki-engine 核心 crate + dotzuki CLI(new/check/run)+ 基础 DSL | 免费开源 | 获客、建立信任、社区口碑 |
| **商业授权层** | 商业使用授权(闭源发布权)、编辑器套件 Pro 功能、平台 shell(Android/iOS)正式支持、优先技术支持 | 按席位/项目授权 或 收入分成,二选一报价 | 主要收入 |
| **SaaS 定制层** | 承接客户定制化诉求:托管编辑器与云编译、定制功能开发、素材/剧情 AI 生成额度、私有化部署、陪跑式接入服务 | 订阅制 + 项目制定制报价 | 高客单、粘性与续费 |

转化路径:**开源免费用 → 要商业发布/要生产力工具时买授权 → 有定制诉求时上 SaaS**。
三层之间必须有清晰的书面边界(哪些 crate 开源、授权覆盖什么、SaaS 包含什么),这是所有宣传物料和报价单的地基,**发布前需法务过一遍**。

## 1. 一句话定位(核心叙事)

**"不写一行 Rust,做出一款可以上架的经典 JRPG。"**

支撑这句话的三个事实(全部可被现场演示验证,不夸大):

1. **零代码做游戏**:`dotzuki new` 脚手架 → `.scene/.gui/.theme` DSL + RON 战斗规则 → `dotzuki run` 直接玩。wuxia 项目即实证。
2. **引擎能力上限已被压测**:pokered 用同一套引擎复刻了 Pokémon Red 的完整逻辑(248 张地图、151 物种、战斗效果栈、跨平台),4,400+ 测试。
3. **全平台一套工程**:native / WASM 浏览器 / Android / iOS / 终端 TUI,同一份游戏数据。

备选 slogan(按渠道选用):
- 技术向:"The battle system is a data file."(战斗规则 = RON 数据文件,策划可直接改)
- 效率向:"From idea to playable JRPG in an afternoon."
- 中文向:"策划写规则,引擎跑战斗。"

## 2. 两个案例的分工(重要)

### ⚠️ pokered 的 IP 风险 —— 必须先定边界

pokered 复刻的是任天堂/Game Freak 的 Pokémon Red。**它不能被包装成"用我们引擎做的商业游戏"来卖**,否则整个销售页面会成为侵权证据。建议的使用边界:

- ✅ 定位为 **engineering case study / 技术压力测试**:"我们用引擎 1:1 复现了一款商业级 JRPG 的完整逻辑,证明引擎表达力上限"。
- ✅ 技术博客、会议演讲中作为"我们怎么验证引擎完备性"的故事讲(复刻既有游戏是常见的引擎验证手段,类比 Godot 社区的 demake)。
- ✅ 素材使用原创重绘或抽象示意图,**不直接使用 Pokémon 官方素材、名称做商业宣传主视觉**。
- ❌ 不做"买我们引擎,做你自己的宝可梦游戏"这类暗示。
- ❌ 销售页、报价单、合同附件中不出现 Pokémon 商标素材。

### wuxia:商业宣传的主角

wuxia 是原创 IP、零 Rust 代码的完整游戏项目,是**唯一可以无风险放大的商业案例**:

- 证明"原创游戏从 0 到可玩"的完整工作流(世界观 docs → 地图 → 剧情 .scene → 战斗规则)。
- 武侠题材对国内市场天然亲和,可直接用于中文宣传主视觉。
- 建议补做:3 分钟实机演示视频 + 一张"从剧情文档到游戏画面"的对照长图。

**案例分工结论:pokered 讲给程序员听(深度、可信度),wuxia 讲给购买决策者看(效果、速度、安全)。**

## 3. 市场策略:国内主线 + 海外探针(不做先验结论)

团队对海外市场没有实操经验,现阶段**不把宝押在任何一边**。结构如下:

### 主线:国内(资源集中地)
理由:团队熟悉渠道与语境、wuxia 武侠题材天然亲和、中文内容产出效率高、SaaS 定制层需要面对面/同语境销售,国内先行能最快跑通"授权 + 定制"的商业闭环。

### 探针:海外(低成本、只投放"自带传播力"的资产)
不建海外运营体系,只做三件低成本高杠杆的事,目的是**收集数据**,为 2-3 个月后的市场决策提供依据:

1. 英文官网落地页 + 英文 quickstart 文档(一次投入,长期有效);
2. 一次 Show HN / r/rust 发布(技术叙事,主打 pokered 验证故事——这类内容在海外社区有自传播力,不需要持续运营);
3. dotzuki-cli 上 crates.io(英文世界的自然流量入口,零维护)。

**决策门**:首发后 4-6 周复盘海外数据(HN 热度、crates.io 下载、海外 waitlist 占比)。若海外自然流量显著超预期,再立项做海外内容运营;若平平,维持探针现状,不追加投入。

## 10. 风险与注意

1. **IP 风险(最高优先级)**:见 §2。所有对外物料发布前过一次"Pokémon 素材/商标检查"。
2. **过度承诺**:宣传中只讲已实现的(Android/iOS shell 的成熟度要在文案中如实标注 beta/实验性,避免交付争议);SaaS 定制层的交付能力要与销售承诺匹配,定制项目容易吃掉全部研发带宽,接单要设门槛。
3. **开源与商业的边界模糊**:三层边界必须尽早写清并公开,模糊会同时吓跑社区和客户。
4. **海外探针变成无底洞**:探针的意义是收集数据,不是"顺便做海外"。第 10 周复盘前不在海外追加任何固定投入。
5. **单一案例说服力**:只有两个案例时,尽早扶持 1-2 个外部开发者用引擎做出 demo(可免费提供支持换案例授权),第三方案例的说服力远超自研案例。
